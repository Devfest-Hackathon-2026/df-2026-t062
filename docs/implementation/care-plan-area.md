## 用紙ナビゲーションの更新

追加更新：中央の `ケアプラン全用紙` 領域で、第1〜7表とそれぞれの全ページを連続スクロール表示する。左一覧は固定し、クリックで中央だけを該当用紙まで移動する。スクロール位置に合わせて左の選択表示を同期する。保存ツールバーは用紙領域内で追従し、下の表での保存が第1表への移動を起こさないようにする。

全表の編集コンポーネントは同時に保持し、スクロールで再マウントしない。記録のAI候補や入力ダイアログの内容も、閉じるたびに作り直さない。第1〜3表の編集・一括保存は1つの状態を共有し、表ごとの入力値は独立したまま維持する。

`codex/care-plan-paper-navigation`（#204を土台）では、上の横タブと第1〜3表の内部ナビを、左の第1〜7表の縦一覧へ統一する。第1〜3表は同じ編集状態を保つ。初期は選択した表だけの表示だったが、現在は上記の連続表示へ変更している。

- 第4〜7表も既存の記録・月次・算定があれば先頭のものを自動表示する。検索・履歴選択や編集途中の状態を、一覧更新だけで上書きしない。
- 未作成でも公開様式の空用紙を表示する。閲覧のために書類・月次・算定を作成しない。入力を始める時点の明示的な作成・生成操作は維持する。
- 第1〜3表の初回表示でも作成ダイアログを自動で開かない。必要な時に「計画を作る」から開始する。
- 公開様式IDは認証済みの `GET /api/form-kinds/:kind/published` で取得する。事業所から見えない種類は返さず、原紙は既存の権限制御と署名付きURLで取得する。
- 左の一覧は表の選択に使い、記録や月の選択・検索は用紙上部の領域へ配置する。用紙の拡大、欄からの編集、保存・確定処理は再利用する。

以下は#205の初期集約時の記録。

- PCの書類タブとiPadの書類メニューに「ケアプラン」を置き、その中で第1〜3表・第4表・第5表・第6表・第7表を切り替える。
- サービス利用票・利用票別表などの入口を、一般書類タブと「書類を作る」から外す。表示可能な書類種別と既存書類を参照する。
- 公式原紙の大きな表示、入力ダイアログ、保存・確定・履歴・PDFの既存処理は再利用する。DB移行や算定範囲の拡張は行わない。
- 一度開いた表はケアプラン内の切り替えで破棄せず、未保存入力・選択位置を保持する。処理中は切り替えを止め、ケアプラン外へ出る場合は未保存入力を確認する。
- 「計画の履歴」は第1〜3表の履歴。他の表を表示中に押した場合も第1〜3表へ戻して表示する。各記録・月次・算定の履歴は従来どおり各画面で扱う。
- E2EでPC/iPadの入口、表の往復と未保存入力保持、既存の保存失敗・履歴・PDF・確定を検証する。
