# 保存・確認・正式確定の分離（#16）

## 状態と更新

| 操作・状態 | 永続化する内容 | 後のAI更新 |
|---|---|---|
| 入力 | `field_values` の現在値。手入力は従来どおり自動保存 | 未確認のAI入力のみ許可 |
| 保存 | `document_saved` と不変の `revisions` | 保存だけでは確認・確定にせず、未確認AI入力の再更新を許可 |
| 内容を確認 | 値を変えず `reviewed_at`・`reviewed_by` を記録。`by` は作者のまま保持 | 作者がAIでも保護 |
| 確認を取り消す | 確認情報を消す。保存版・正式版は保持 | AI入力は再更新可能。手入力の保護は維持 |
| 人が編集 | `by=cm`。値が変わると確認を外す | 手入力による保護を維持 |
| 正式確定 | 現在値と一致する最新の保存版に、担当者・日時を追記 | 正式版の内容は変えない。以後の作業は別の入力・保存版として扱う |

一般書類に `POST /api/documents/:id/review` と `POST /api/documents/:id/confirm` を追加。ケアプラン第1〜7表の正式確定は既存の専用APIを使い、一般書類の確定APIでは拒否する。

確認APIには表示した様式版、各欄の値、`valueVersion` を渡す。書類ロック中にすべて照合し、1つでも違えば全体を409で拒否する。値が一度変わって同じ値へ戻った場合もUUIDが異なるため拒否する。確認時に保存・作者・値は変えない。AIのバッチ適用は確認済みを `kept(reason=reviewed)` にし、それ以外のAI書き込み経路も `writeField` で拒否する。

確定は、最新の保存版番号・様式版・現在値の一致・全入力値の確認を必要とする。二重実行は既存の確定日時と担当者を維持する。正式版の記録はDBトリガーで更新・削除を禁止する。空欄の必須チェックや医学的・制度的な内容の審査を代行するものではない。

## 画面と出力

PCとタブレットの「確認・確定」から、表示した内容の確認、確認の取り消し、正式版の確定を行う。閉じるまで表示対象を固定し、サーバーとの競合時は開き直しを促す。図は既存の図プレビューで表示する。

ペットの確認一覧も、保存済みかではなく明示確認の状態を見る。通常のPDF出力は従来どおり最新の保存版。「正式版を出力」は確定した版番号を指定する。正式版の後に編集・保存したときは、正式版と現在の作業を区別して表示する。

## 移行と検証

`0038_document_review.sql` をアプリ更新前に適用する。既存の入力・保存版の内容と作者は変えず、確認・正式確定は未実施の状態から始める。新旧APIの混在期間に確認保護を回避しないよう、APIとworkerを同じ版へ更新する必要がある。

- `test/core.test.ts`: 確認済みAI・空欄・システム値の保護。
- `test/api.test.ts`: 保存後のAI更新、明示確認、確認取り消し、別経路のAI更新拒否、ABA競合、古い保存版、未保存値、二重確定、他事業所、確定後の編集と保存版保持。
- `test/pet-assessment.test.ts`: 保存だけで確認済みにしない。
- `test/document-input-migration.test.ts`: 既存の保存済みAI入力を確認済み・正式版にしない。
- `e2e/document-review.spec.ts`: PC実画面→API→隔離DBで、保存・確認・確定・競合・再表示。

外部AI、本番DB、実利用者情報を使わない検証。iPad実機での操作確認はこのPRでは未実施。
