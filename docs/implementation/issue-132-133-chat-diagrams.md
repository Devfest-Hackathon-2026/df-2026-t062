# #132・#133 チャット中心の家族図・身体図

PR #127の構造化図・版番号・保存・PDF出力を継承する追加変更。家屋見取図の操作は変更しない。

## 操作

- 家族図・身体図の用紙上の欄を押すと、既存の「書き方を相談する」へ移る。指示を入力し、送信する。人物パレットや手動の線・座標調整は通常画面に出さない。
- チャット内では変更後の図1枚と人物・関係・症状ごとの変更点を表示する。内容と参照原文は必要時に開く。
- 「用紙に反映」を押すまで書類を変えない。反映後も保存版は別で、ページ／書類の保存で確定する。取り消した変更も未保存であることを区別する。
- 「この案を修正」では未反映案も参考として送る。用紙の現在値を別途読み直し、古い案を自動適用しない。新しい案が届くまでは元の案を保持する。
- 身体の位置が不明なときだけ「図上で場所を指定」が出る。対象を選び、正面／背面を選択し、一度押す。矢印キーとEnterも使用できる。指定待ちが残る案は反映できない。通常のプレビューにはドラッグ操作を付けない。

## 図を選んで相談する経路（2026-11-21追加）

- 図を押して開いた相談では、自然言語の見出しだけでなく `diagramField` に安定したフィールドIDを付けて送る。公開様式にない図、修正案と異なる図はAPIで拒否する。一般の書き方相談の経路は残す。
- 対象の図・shape・revision、書類の根拠、録音の先頭ページをサーバーが先に取得してAIに渡す。図専用の指示と道具に絞り、不要な読み直しを減らす。長い録音の続きは引き続き取得が必要で、読み残した記録からの提案は通さない。
- 指定外の図や文章欄への変更案は、モデルの回答に含まれていても受け付けない。相談先を変えるには、用紙の別の図を押す。
- 混雑、利用上限、時間切れ、接続権限、モデル設定の失敗を固定文言で表示する。プロバイダーの生のエラー文やAPIキーは画面に返さない。失敗を成功扱いせず、既存の図・案・送信した文章を保持する。送信中に別の文章を書いた場合や図を切り替えた場合も、それぞれの下書きを残す。
- モデル呼び出しは1回60秒、相談全体は2分の期限を設ける。SDK内の自動再試行を止め、一時的なエラーのみ外側で最大1回再試行する。認証や不正リクエストは繰り返さない。Google側の503を解消する変更ではない。

## 情報源と検証

`read_form` / `propose_edit` を再利用し、同じエージェントへ `read_diagram_context` と `read_records` を追加した。独立した生成AIエンドポイントや画像生成は追加していない。

- 同一事業所・同一利用者の書類の実際の値と、録音の文字起こしを読む。保存版と現在値が異なる場合は両方を返し、状態を区別する。
- 録音はキーワードに依存せず順に取得する。長い発言も分割する。未取得部分がある記録由来の案は拒否する。取得完了は医学的・意味的な抽出の網羅性を保証するものではない。
- 独立した訪問メモの保存・取得経路は見つからなかった。書類の欄に保存済みの記載は参照できるが、メモを読み込めるとは表示しない。
- 出典IDは取得した書類・発言・利用者のチャット指示に限る。表示する原文はサーバーでコピーする。モデルが渡す原文や架空の出典は採用しない。変更したオブジェクトの内部データに出典を保持する。
- 既存オブジェクトIDを維持し、申告された変更対象IDと実際の差分を照合する。無関係なオブジェクトは元の値へ戻す。削除や生死の断定には明示的な根拠を要求する。
- 元の図と版番号の不一致は既存PATCHで拒否する。通信失敗・再試行・取り消しでも既存図を維持する。

意味の解釈はモデルに依存する。宣言された対象IDの検証は、自然言語の依頼との完全な一致を証明するものではない。根拠の存在確認と、内容の妥当性の人による確認を混同しない。

## 表示上の意味

- 家族図は親子の世代と同居／別居・不明のレーンで自動配置する。同居外の人物が同居枠に入らない配置にする。旧データの人物ID・関係IDは維持する。
- 生死が不明な新しい人物は `deceased:null`。性別不明・年齢不明・同居不明も推測で埋めない。
- 身体図の左右は本人基準。部位と正面／背面から、同梱の人体図の位置へ決定的に配置する。正面と背面を鏡像として取り違えない。
- 広い背中・腰の表現は領域として扱い、点を断定しない。部位が特定できないものは案の `pendingLocations` に分離し、未確定座標を保存しない。
- 「しびれ」は注記。麻痺などへ変換しない。医学的分類には、それを肯定している原文を要求する。本人の訴えは `※` と表示し、帳票の障害部位の印と区別する。
- 描画は編集プレビュー・用紙・PDFで共通。異なる部位への訂正でも他の症状を保持する。

# ?entry=1 を付けると実際の右パネルで図タップ→相談画面の入口を確認できる
# ?entry=1&chatError=503 で混雑を再現（実AIは呼ばない。504・429も指定可）

# 実際のGeminiを使用する。費用が発生する。実在の利用者情報は含めない

# DIAGRAM_CASE=body-target-correction で1ケースに絞れる
# DIAGRAM_EVAL_OUTPUT=/tmp/diagram-results.json で架空データの結果を書き出せる

未確認: 実タッチ端末、高齢者本人の試用、スクリーンリーダー、狭幅と文字拡大の実寸操作。多量の記録では既存のエージェント呼び出し上限内に取得を完了できない可能性があり、その場合は案を出さない。実モデルでは1回の応答に数分かかる例があり、運用前の応答時間確認が必要。これらを残したドラフトPRとし、mainへはマージしない。
