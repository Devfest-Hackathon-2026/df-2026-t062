# 録音からの書き込み

状態: 下書き（2026-11-19）

録音から AI が書類の欄を書く仕組みを、今の 2 層改から作り替える設計。書類の種類と様式によらず、同じ形で動く。表の形は [13_DB設計.md](13_DB設計.md)、様式の側（書類の欄、その様式だけの欄）は [16_書類と点検の基盤.md](16_書類と点検の基盤.md)。

## 決めたこと（2026-11-19）

| 決めたこと | 中身 |
|---|---|
| 文字起こしを全部読むのは 1 回 | AI が文字起こしの全部を読むのは、要約するときの 1 回だけ。書くときは要約を読む |
| 種類ごとに「まとめる項目」を持つ | 書類の種類ごとに、まとめる項目の一覧を持つ。要約も書き込みも、この項目の単位で行う |
| 要約する | 録音ごとに、項目ごとの要約を作る。要約の中で発言を引用してよい |
| 要約を足していくかは種類ごと | 種類ごとに、要約を前の回に足していく（例: アセスメント）か、録音ごとに単体で使う（例: 担当者会議の記録）かを決める |
| 要約は見せない | 要約はケアマネに見せない。直す入口も作らない |
| 書く欄は AI が選ぶ | AI が要約を見て、様式のページごとに書く欄を選ぶ。足していく種類の 2 回目からは、要約に今回足した分の印を付け、欄の今の値も見せる |
| 最後のチェック | 最後にチェックする AI が、不要な部分と、要約に根拠のない部分を切る。今の「読み直し」の役目もここにまとめる |
| 全体のまとめは最後 | 全体のまとめは、ほかの項目を書いたあとに書く |
| 日付は機械 | その日の日付（実施日）は機械で入れる。AI には書かせない |
| 23 項目の番号を外す | 欄に付けていた 23 項目の番号（fields.json の `item23`）はやめる |
| 23 項目は改正後の名前 | アセスメントのまとめる項目は、令和5年の改正後の課題分析標準項目の名前にする。改正後の「生活リズム」が 1 日のスケジュールに当たるので、1 日のスケジュールの項目は別に立てない |
| 根拠は要約の行まで | 値の根拠には、もとにした要約の行を残す。元の発言まではたどらない。ケアマネには出さない |
| 費用の上限 | 録音 1 本の書き込み（要約から最後のチェックまで）で 200 円 |
| 責任者が項目を直せる | 事業所の責任者が、要約の項目を足したり、全体の項目の説明に書き足したりできる。何を特に聞き取ってほしいか、何を書き漏らさないでほしいかを、AI に明示できる |

2026-11-09 に「録音と欄の間に、事実の層は作らない」と決めた。要約はその決めを変える。録音と欄の間に、項目ごとの要約が入る。

### 今との違い

| | 今（2 層改） | 変えたあと |
|---|---|---|
| AI が文字起こしを読む回数 | 録音の全部を 8 回ほど（まとまりごとに毎回全部） | 新しい録音を 1 回（要約するときだけ） |
| 書くときに AI が読むもの | 録音の文字起こしの全部 | 項目ごとの要約 |
| どの欄に書くか | 欄に付けた 23 項目の番号で決め打ち | AI が要約を見て、ページごとに選ぶ |
| AI を呼ぶ単位 | 23 項目を 7 つにまとめたもの（アセスメント専用） | 種類ごとのまとめる項目 |
| 根拠の確かめ | 読み直し（録音と照らす） | 最後のチェック（要約と照らす） |
| 日付 | 機械 | 機械（同じ） |
| 事業所ごとの指示 | できない | 責任者が、要約の項目を足す・説明に書き足す |

## 流れ

```mermaid
flowchart LR
  A["録音"] --> B["文字起こし・話した人"]
  B --> C["要約（項目ごと）"]
  C --> D["書く欄を選ぶ（ページごと）"]
  D --> E["項目ごとに書く"]
  E --> F["全体のまとめを書く"]
  F --> G["最後のチェック"]
  G --> H["書類に入れる・日付"]
```

| 段 | すること | AI に渡すもの | AI の答え |
|---|---|---|---|
| 1. 録音 | ケアマネが書類を開いて録音する。録音はその書類につながる。書類を指定しなければ、主な書類につながる | — | — |
| 2. 文字起こし | 文字起こしをして、話した人（本人・家族など）を割り当てる（今と同じ） | — | — |
| 3. 要約 | 新しい録音を 1 回だけ全部読み、まとめる項目ごとに要約する | 新しい録音の文字起こしの全部、その事業所の項目の一覧（名前と説明。下の「事業所が直せる項目」） | 項目ごとの要約。話に出なかった項目は空 |
| 4. 書く欄を選ぶ | 様式のページごとに、書く欄を選ぶ | 全部の項目の要約（下の「使う要約」）と項目の説明、そのページの書いてよい欄（名前・型・選択肢・説明書き）。足していく種類の 2 回目からは、今回足した分の印と、欄の今の値も | 書く欄と、その欄を書くときに読む項目（1 つ以上） |
| 5. 書く | 項目ごとに、選ばれた欄を書く | 読む項目の要約（使う要約）、書く欄の定義、書き方の決まり | 欄の値 |
| 6. 全体のまとめ | 最後に書く項目の欄を書く | 全部の項目の要約、5 で書いた値 | 欄の値 |
| 7. 最後のチェック | 不要な部分と、要約に根拠のない部分を切る | 書いた値（文・選択肢の単位に分けたもの）、要約。項目の説明は渡さない | 切る部分 |
| 8. 書類に入れる | 型を確かめて書類に入れる。その日の日付を機械で入れる | — | — |

### 使う要約

4〜7 で使う要約は、種類の設定（`form_kinds.summary_mode`）で決まる。

| 設定 | 使う要約 | 例 |
|---|---|---|
| 足していく（`append`） | その書類につながった録音の要約を、1 回目から全部 | アセスメント |
| 単体（`single`） | 今回の録音の要約だけ | 担当者会議の記録、モニタリングの記録 |

## まとめる項目

書類の種類ごとに、`form_kinds.topics`（13）に持つ。1 つの項目は次のものを持つ。

| 属性 | 中身 |
|---|---|
| `id` | 項目の id。名前を変えても変えない |
| `name` | 名前（例: 健康状態） |
| `guide` | 何をまとめるか。要約する AI と、欄を選ぶ AI への手がかり。「この話は○○の欄に書く」のように、書く欄の手がかりも書ける |
| `by` | `ai`（AI が要約して書く）か `machine`（機械で入れる） |
| `last` | 最後に書く項目か（全体のまとめ） |
| `keys` | `machine` の項目だけ。入れる欄（`{"first": 1 回目の欄, "later": 2 回目からの欄}`） |

アセスメントの最初の一覧:

| 項目 | 書き方 |
|---|---|
| 課題分析標準項目の 23 項目（令和5年の改正後）: 基本情報（受付、利用者等基本情報）、これまでの生活と現在の状況、利用者の社会保障制度の利用情報、現在利用している支援や社会資源の状況、日常生活自立度（障害）、日常生活自立度（認知症）、主訴・意向、認定情報、今回のアセスメントの理由、健康状態、ADL、IADL、認知機能や判断能力、コミュニケーションにおける理解と表出の状況、生活リズム、排泄の状況、清潔の保持に関する状況、口腔内の状況、食事摂取の状況、社会との関わり、家族等の状況、居住環境、その他留意すべき事項・状況。番号は付けない | AI |
| 全体のまとめ | AI。最後に書く |
| その日の日付 | 機械。1 回目は実施日（初回）、2 回目からは実施日（更新） |

- 名前は、令和5年10月16日の課題分析標準項目の改正の通知の表から写す。1 日のスケジュールは「生活リズム」に入る。
- ほかの種類（モニタリング、担当者会議の記録など）は、種類を足すときに、その種類の項目の一覧を作る。
- 項目の一覧が空の種類は、録音から書かない。
- 「1 回目」は、その書類に、録音から AI が書いたことがまだないとき。
- 録音の日を入れる欄は機械の項目、録音のたびに書き直す案の欄は最後に書く項目として、この一覧で決める。
- 事業所は、この一覧に項目を足したり、説明に書き足したりできる（下の「事業所が直せる項目」）。

## 事業所が直せる項目

事業所の責任者は、まとめる項目を、事業所ごとに足したり書き足したりできる。何を特に聞き取ってほしいか、AI が何を書き漏らしているかを、AI に明示するため。

| できること | できないこと |
|---|---|
| AI がまとめる項目を足す（名前と説明）。足した項目は、あとで直せる・消せる | 全体の項目を消す・名前を変える |
| 全体の項目の説明に書き足す。書き足した文は、あとで直せる・消せる | 機械の項目と、最後に書く項目を足す |

例:

| したいこと | 直し方 |
|---|---|
| 点検で「1 日の水分量」がいつも抜けるので、書き漏らさないでほしい | 「健康状態」の説明に「水分量は、量を数字のまま残す」と書き足す |
| 事業所の用紙にある「ペットの有無」を、必ず聞き取ってほしい | 項目「ペット」を足し、説明に「ペットの有無と、世話を誰がしているか。この話は『ペットの有無』の欄に書く」と書く |

- 録音の処理が使う一覧は、全体の一覧（`form_kinds.topics`）に、その事業所の書き足しと、足した項目を合わせたもの。事業所が何も直していなければ、全体の一覧をそのまま使う。全体の一覧をサイト管理者が直すと、どの事業所にも効く。
- 項目の説明は、3（要約）と 4（欄を選ぶ）に渡す。7（最後のチェック）には渡さない。推測で書かない決まりと最後のチェックは、説明では変えられない。説明に何が書いてあっても、要約に根拠のない部分は切る。
- 直したあとの録音から効く。前の録音は要約し直さない（作った要約は書き換えない）。
- 足していく種類で、足した項目の要約がまだ 1 つもなければ、面談のヒントに「まだ聞いていない」と出す。要約の中身は出さない。
- 直せるのは責任者だけ（14 の `form.manage`）。直したことは、今の操作の記録（`audit_events`）に残す。
- 録音の処理は、使った一覧の指紋を残す。事業所が直す前と後で、書き込みを比べられるようにするため。
- 責任者の画面の見た目は、別に描いて相談する。

## 要約

- 録音 1 本ごと、項目ごとに 1 つ作る。作った要約は書き換えない。
- 前の回に足していくか、単体で使うかは、種類ごとに決める（上の「使う要約」）。
- 要約の中で発言を引用してよい。引用は「」で原文のまま書く。
- 話に出なかった項目には作らない。
- ケアマネには見せない。要約に誤りがあっても、ケアマネが直した欄は、AI は書き換えない（書き換えの決まり）。

例（足していく種類）:

```
主訴・意向
  1 回目（11/10）「できるだけ自分でやりたい」と自立を強く望む。
  2 回目（11/24）排泄は、自分 1 人では難しい。
```

## 書く欄を選ぶ

- 選べる欄（候補）は、書類が指す様式の版が読む欄のうち、AI が書いてよい欄。
  - 出どころに会話か案がある欄（16 の「録音から AI が書く欄」）
  - その様式だけの欄は、説明書き（`note`）があるもの
- 様式のページごとに 1 回呼ぶ。候補がないページは呼ばない。
- 足していく種類の 2 回目からは、要約に今回足した分の印を付け、そのページの欄の今の値も添える。AI は、空の欄と、今回の話で変わる欄を選ぶ。今回の話に関わらない欄は、そのまま残る。
- 答えは、書く欄と、その欄を書くときに読む項目（1 つ以上）。候補にない欄を答えても書かない。

## 書く・全体のまとめ

- 項目ごとに 1 回呼ぶ。4 で選んだ欄は、最初に挙げた項目のところで書く。挙げた項目の要約は全部渡す。
- 書き方の決まり（推測で書かない、表の列の決まり、置き場所の決まり）は、今のものを使う。
- 指示文には、書類の種類の名前と、欄の用紙での場所（版のページと印字欄）を差し込む。決まりの文は先頭に置き、どの呼び出しでもそろえて、キャッシュに当てる。
- 全体のまとめ（`last` の項目）は最後に書く。全部の項目の要約と、5 で書いた値を読む。4 で「全体のまとめ」を読む項目に挙げた欄を書く。
- 値の根拠には、もとにした要約の行（項目と回）を残す。元の発言まではたどらず、ケアマネにも出さない。

## 最後のチェック

- 書いた値を、文章は 1 文ずつ、選択肢は 1 つずつに分けて確かめる。
- 切るのは次の 2 つ。
  - 不要な部分
  - 要約に根拠のない部分（推測で書いたもの、今のことではないもの、ケアマネが決めることを含む）
- 「不要な部分」として指示文に書く例:
  - 同じ欄の中で、同じことを繰り返している部分
  - その欄の名前・説明に合わない話（ほかの欄に書くべきこと）
  - 書類に残さなくてよい話（挨拶、雑談、ケアマネ自身の段取り）
  - 中身を足さない前置き（例:「録音によると」「本人の話では」）
- 項目ごとに 1 回呼ぶ。書いたときと同じ要約を渡す。
- 全部切られた欄は書かない。前の値があれば残す（AI は欄を空にしない。今と同じ）。

## 書類に入れる

- 型を確かめる。通らない値は落として数える（今と同じ）。
- 書き換えの決まりは今と同じ。空の欄には足し、AI が書いた値は直し、ケアマネが書いた値は残す。
- その日の日付は、機械の項目の `keys` の欄に入れる。1 回目は `first` の欄（空のときだけ）、2 回目からは `later` の欄。
- 値が入るのは、録音がつながった書類だけ。同じ利用者のほかの書類は変わらない。

## 失敗したとき

- 段ごとに進み具合を残し、止まっても続きから進める（今と同じ）。
- 要約は残るので、4 から先で失敗してやり直しても、要約はし直さない。
- 一部の項目が失敗しても全体は止めず、終わりの状態を「一部」（`partial`）にする（今と同じ）。

## テスト

新しい決まりは Red（落ちるテスト）から書く。偽の Gemini で書けるものは偽で書く。

| 段 | 先に書くテスト | 種類 |
|---|---|---|
| 要約 | 要約は足すだけで、前の回の要約は変わらない。話に出なかった項目は行を作らない。単体の種類は、前の回の要約を使わない。要約は API で返さない | Red から |
