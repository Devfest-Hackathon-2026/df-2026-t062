# 画面のコード（src/）の置き場所

画面・機能が増えても置き場所に迷わないように、次の決まりで置く（#158）。決まりの一部は `test/src-layout.test.ts` で確かめている。

## 上の段は 4 つだけ

| フォルダ | 置くもの | 単位 |
|---|---|---|
| `app/` | 起動と画面の切り替え（ログインしているか、URL とどの画面を出すかの対応、全体の CSS） | — |
| `screens/` | 画面そのもの。部品をどこに並べるかだけを書く | **1 フォルダ = 1 画面**（1 つの URL） |
| `components/` | 機能の部品と処理。画面に出ない処理（値の計算、録音の保存など）も同じフォルダに入れる | **1 フォルダ = 1 機能** |
| `lib/` | 業務を知らない道具（API の呼び出し、アップロード、ダウンロード、ログイン、URL の移り方） | — |

`main.tsx` は起動の入り口なので、上の段に置く。

## 読み込む向き

```
app → screens → components → lib
```

- 読み込めるのは、右（下の段）にあるものだけ。左を読み込まない（例: `components/` から `screens/` を読み込まない）。段を飛ばして読み込むのはよい（例: `app/` から `components/`）。
- `screens/` どうしは読み込まない。2 つの画面で使うものは `components/` に置く。
- `components/` どうしは読み込んでよい。ただし輪にしない（A が B を読み、B が A を読む、をしない）。輪になりそうなら、両方が使う部分を別の機能に分ける（例: 猫の見た目 `pet/` は、猫の手伝い・点検・書類の取り込みが使うので独立させた）。
- 画面で使う枠の部品（ヘッダー、責任者の画面の枠）は `app/` ではなく `components/` に置く。`app/` に置くと `screens/` から `app/` を読み込むことになり、向きが逆になる。

## 名前の付け方

- `components/` のフォルダの名前は、プロダクトの言葉で付ける（`document`、`recording`、`assistant` など）。
- `screens/` と `components/` の中に、さらにフォルダを作らない。大きくなったら、機能を 2 つに分ける。
- 画面に出す部品は `PascalCase.tsx`、その CSS は同じ名前で横に置く（例: `PetHelper.tsx` と `PetHelper.css`）。それ以外は `camelCase.ts`。
- フォルダの名前は英小文字とハイフン（例: `client-work`、`document-input`）。
- `ui/`・`hooks/` のような、種類で分けるフォルダは作らない（1 つの機能が散らばるため）。

## いまの中身

### app/

| ファイル | 中身 |
|---|---|
| `App.tsx` | ログインの確かめと、URL・端末（PC か iPad）・役割からどの画面を出すかの切り替え |
| `routes.ts` | URL と画面の対応（`Route`・`parse`・`useRoute`） |
| `styles.css` | 全体の CSS |

### screens/

| フォルダ | URL | 画面 |
|---|---|---|
| `login/` | `/login`（ログインしていないとき） | ログイン |
| `client-list/` | `/` | 利用者一覧（`PcList`・`PadList`） |
| `client-work/` | `/clients/<id>` | 利用者の書類を作る画面（`PcWork`・`PadWork`）。新しい書類のメニュー `docMenu.ts` |
| `office-forms/` | `/office` | 責任者: 書類の設定（一覧） |
| `office-kind/` | `/office/forms/<種類>` | 責任者: 書類の画面（書式） |
| `office-upload/` | `/office/forms/<種類>/upload` | 責任者: 書式を上げる |
| `office-review/` | `/office/forms/<種類>/review/<版>` | 責任者: 読み取った書式を確かめる・直す |

PC と iPad で画面が違うときは、同じフォルダに `Pc〜`・`Pad〜` で並べる。

### components/

| フォルダ | 機能 |
|---|---|
| `document/` | 用紙の表示と書類の状態（ページの描画、欄の値の持ち方、差分の見せ方、欄の名前と位置、用紙の上の図の欄） |
| `recording/` | 録音（録る、端末に残す、送る） |
| `assistant/` | 猫の手伝いの枠と「書き方を相談する」チャット（聞き取りの話題、確かめる項目、図の案の確認） |
| `pet/` | 猫の見た目（アイコン、吹き出し） |
| `inspection/` | AI 点検 |
| `document-input/` | 書類の取り込み（画像・PDF を添付して欄に入れる） |
| `survey/` | 認定調査票の読み取りと、用紙に入れる前の下書き |
| `diagram/` | 図（家族構成図・身体図など）の表示と編集 |
| `care-plan/` | ケアプラン（第 1〜3 表）の画面と保存 |
| `header/` | PC の上の帯とロゴ |
| `office-shell/` | 責任者の画面の外枠（上の帯と左のメニュー、戻るリンク） |
| `form-status/` | 責任者の画面で使う、書類ごとの書式の様子（読み取り中・読めなかったなど） |

### lib/

| ファイル | 中身 |
|---|---|
| `api.ts` | API の呼び出し |
| `chatStream.ts` | チャットの返事を少しずつ受け取る |
| `upload.ts` | 大きなファイルを、途中から続けられる形で送る |
| `download.ts` | ファイルを端末に保存させる |
| `auth.tsx` | ログイン |
| `router.tsx` | ページを読み込み直さずに URL を変える（`navigate`・`linkProps`）、PC か iPad かの見分け（`useDevice`） |
| `jobStatus.ts` | 書けなかった欄の key を、読める名前にする（欄の一覧を知っているので、業務を知らない道具とは言い切れない。#158 では動かさなかった） |

## 新しく足すとき

1. 新しい URL の画面なら `screens/<画面の名前>/` を作る。画面のファイルには部品の並びだけを書き、部品と処理は `components/` に置く。
2. 新しい機能なら `components/<機能の名前>/` を作る。今ある機能の一部なら、そのフォルダに足す。
3. 業務を知らない道具なら `lib/` に足す。
4. `node --test test/src-layout.test.ts` で、向きと輪を確かめる。
