# #18 の確認時間を測る手順

実モデルの処理時間だけでは、作業が軽くなるとは判断できない。ケアマネが架空の資料を照合し、修正・採用を終えるまでを手入力と比較する。自動テストや開発者の操作をケアマネの実測の代わりにしない。

## 比較する作業

`survey-clean.pdf` の第2群12項目を、同じ版の空のアセスメントへ入力する。正解は [gold.tsv](survey/gold.tsv) の `2-1`〜`2-12`。取込経路は現在の最新版を使用する。2026-11-21の方針に合わせ、原本表示や本人確認チェックは要求せず、反映先とAI判定の確認・採用、および必要な用紙上の修正を測る。取込画面では判定値を編集せず、反映の有無だけを選ぶ。PDFに加え、同じ情報の画像添付も試す。

1. 手入力：資料を開いて開始し、12項目の入力と見直しが終わるまで測る。
2. 取込：ファイル選択から測り、読み取り待ちと実際に操作した時間を分ける。AIの判定内容と反映先を確認し、採用する項目だけ反映する。誤判定は反映せず、必要な用紙上の入力・修正を含めて12項目が完成したところで止める。
3. 実施順を入れ替えてもう一度測る。同じ資料を覚える影響があるため、1人・1回の値だけで改善と断定しない。
4. `survey-difficult.pdf` と `survey-blank.pdf` で、保留の意味と原文を理解できるか確認する。難読欄は推測で埋めず、確認が必要なままにする。

2026-11-20、ユーザーと確認し、この時間比較はコードレビュー開始後の受け入れ確認として実施する。Draft解除はレビュー開始を意味し、時間比較の達成や本番利用の承認を意味しない。テスト成功や候補一致率だけで、この確認作業を実施済みと扱わない。
